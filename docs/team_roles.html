AML Insight 智慧金流風險分析平台：三人分工表

結合圖神經網路與可解釋人工智慧之異常金流偵測與潛在洗錢網絡分析系統。每位成員負責固定的資料夾，避免改到同一批檔案；所有交接點列在最後。

開工前必讀：第一週已發現金額小於 100 的交易 100% 發生在詐欺帳戶之間（模擬器產物），以及 fraudStep 欄位會洩漏標籤。所以所有模型都要跑 S1（含金額特徵）與 S2（不含金額特徵）兩種設定，且 isFraud、fraudStep 不得當作特徵。詳見 repo 的 docs/data_dictionary.md 與 docs/modeling_decision.md。

產出是 B、C 的輸入，進度不能落後

把原始交易資料變成模型可以用的乾淨資料、特徵和圖。

週次工作內容驗收標準
W1
  1. 用 notebook 親自驗算報告的關鍵數字：詐欺比例、fraudStep 交叉表、金額小於 100 的規則
  2. EDA：金額分布、每個 step 的交易量、依標籤分組的度數分布
  3. 決定 self-loop（15 筆）、重複交易（1,684 筆）、無交易帳戶（20 個）的處理方式
 數字和報告一致；至少 6 張 EDA 圖，每張附解讀；處理方式與理由寫入資料字典
W2
  1. 資料清理模組 data/clean.py
  2. 帳戶特徵模組 features/account.py：轉入／轉出次數、金額總和與平均、入度／出度、淨流量、交易間隔、活躍 step 數
  3. 特徵分成「金額類」與「非金額類」兩組，供 S1／S2 使用
  4. 特徵函式可指定只用 step ≤ T 的交易，供 E3 時間切分使用
 輸出 data/processed/features.parquet；有測試證明 T=89 時不會用到之後的交易；文件列出每個特徵的定義
W3
  1. 圖建構模組 graph/build.py：帳戶為節點、轉帳為有向邊
  2. 同一對帳戶間的多筆交易聚合成邊特徵（次數、金額總和、最早與最晚時間），不能直接丟掉
  3. 鄰居特徵：鄰居數、局部密度、2-hop 鄰居數
  4. 輸出 NetworkX 圖（給平台）與 PyG Data（給 C）
 C 能直接載入 PyG Data 訓練；節點數 20,000；邊數與原始交易數對得上
W4
  1. 資料洩漏總檢查：確認特徵沒有用到標籤、fraudStep 或未來交易
  2. 分析 576 個沒有小額交易的詐欺帳戶和其他詐欺帳戶的差別
 docs/leakage_checklist.md；難辨識子集分析報告
W5準備 E2 消融實驗的資料變體：移除部分節點特徵、保持度數的隨機重接邊、移除邊 每個變體都有可重現的產生函式，並固定 seed
W6平台資料：交易列表、帳戶列表、局部子圖查詢函式（給定帳戶回傳 1～2 層鄰居） C 能在 Streamlit 中呼叫，回應時間 1 秒內
W7–8論文「資料與方法」章節：資料描述、前處理、特徵、圖建構、資料限制 初稿完成，所有數字都來自實際程式輸出

要先學的：pandas groupby／merge、NetworkX 基本操作、PyG Data 格式（x、edge_index、edge_attr）

週次工作內容驗收標準
W1

 測試以手算小例子驗證指標；三份切分不重疊，正樣本比例差小於 0.5 個百分點；三人審過協定

 每個實驗產生 experiments/<id>/metrics.json；閾值只在 validation set 決定
W3XGBoost 超參數調整（只用 validation set）：max_depth、learning_rate、n_estimators 等 調參紀錄完整；test set 只評估一次
W4
  1. E1 主要模型比較：Rule-based、XGBoost、GraphSAGE（C 提供），S1、S2 都要跑
  2. 錯誤案例分析：哪些詐欺帳戶所有模型都抓不到
 比較表與 PR 曲線；錯誤案例報告
W5
  1. SHAP：全域特徵重要度、Summary Plot、個別預測解釋
  2. E2 消融實驗（用 A 的資料變體）
  3. 解釋忠實度：移除 SHAP 最重要特徵後，預測分數下降多少
 SHAP 圖表；消融結果表；忠實度分析
W6E3 時間切分實驗（用 A 的時間視窗特徵） 時間切分與隨機切分的效能比較

全員共同責任

  • 每週例會約 1 小時，紀錄寫在 docs/meetings/weekN.md

GitHub 規則

  • 分支命名：feat/<成員>-<主題>、fix/…、exp/<實驗代號>（例：feat/b-metrics）
  • Commit 訊息：<type>: <說明>，type 為 feat / fix / data / exp / docs / refactor / test
  • 不要 commit：原始資料、模型權重、.env（已在 .gitignore）

第一天：在自己的電腦上建好環境

  1. 接受 GitHub 邀請：到 github.com/Rain931101/aml-insight/invitations 點 Accept（7 天內有效）。
  2. 打開「終端機」（Terminal），一次執行一行： 
    git clone https://github.com/Rain931101/aml-insight.git
cd aml-insight && uv sync && bash scripts/00_fetch_amlsim_samples.sh
uv run python scripts/02_label_quality_analysis.py && uv run pytest
  3. 確認跑出的報告數字與 repo 一致（主要資料集詐欺帳戶 1,804 個、9.02%），測試全部通過。

還沒有 uv：先執行 brew install uv；沒有 Homebrew 要先安裝 Homebrew。使用 Windows 的組員請先告知，指令不同。
