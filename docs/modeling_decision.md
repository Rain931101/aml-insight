# 建模任務決策（Week 1 結論，依實際資料）

> 狀態：Week 1 初版，Week 2 開始前由三位成員共同確認。所有內容為研究設計，**不是實驗結果**。

## 1. 預測單位：帳戶層級節點分類（Node Classification）

| 選項 | 判斷 | 理由 |
|---|---|---|
| **帳戶層級（isFraud）** | ✅ 主任務 | 資料唯一真實標籤在帳戶層級 |
| 交易層級 | ❌ 不作為主要評估 | 交易沒有標籤；「兩端皆詐欺」是弱標籤，會把詐欺帳戶間的一般交易也算成正樣本 |
| 群組層級 | ❌ | 沒有 pattern / alert ID |

- 平台的「交易分析」頁面：交易風險分數 = 由兩端帳戶分數推導（例如 max(sender, receiver)），**明確標示為衍生分數**，不報告交易層級的 precision/recall。
- 主要資料集：`20K_fanin200cycle200`（正樣本最多、同時含兩種模式）。

## 2. 特徵使用規則

- 排除：`isFraud`（標籤）、`fraudStep`（單向洩漏）。
- 保留：由交易計算的帳戶行為、時間與圖結構特徵；`init_balance` 歸在 amount 群組，僅 S1 使用、S2 排除。
- 防止時間洩漏：E3 時間切分時，特徵只能用切分時點之前的交易計算。

## 3. 金額捷徑的處理（影響 RQ1）

因為「金額 < 100」幾乎完美辨識 2/3 正樣本，模型比較至少做兩種設定：

| 設定 | 內容 | 目的 |
|---|---|---|
| S1 Full | 所有合法特徵（含金額） | 一般情境下的效能 |
| S2 Amount-controlled | 移除 amount 群組，包含 `init_balance` 與所有交易金額衍生特徵；只用行為次數、時間與結構特徵 | 檢驗「圖結構」本身是否帶來額外資訊，而非只學到金額或餘額訊號 |

另外錯誤分析需單獨報告「沒有小額交易的詐欺帳戶」子集的 recall。

## 4. 資料切分（初版，Week 2 確認）

- 主實驗（E1/E2/E5）：分層隨機切分帳戶 60/20/20（train/val/test），固定 seed 清單 `[0, 1, 2, 3, 4]`；GraphSAGE 採 transductive 設定（全圖可見、只用 train 標籤計算 loss）。
- 閾值只在 validation set 決定；test set 只評估一次。
- E3 時間切分：候選方案為「特徵視窗切分」（以 step ≤ 89 的交易建特徵與圖訓練，以 step 90–149 的交易重新建特徵測試）。注意 fraudStep 有效值在前 60% 只占約 41%，需在 Week 3–4 驗證可行性後定案。

## 5. 主要指標

PR-AUC（Average Precision）、Precision@K / Recall@K（K = 100, 500, 正樣本數）、F1（val 決定閾值）、ROC-AUC 為輔。

## 6. 尚待驗證的風險

- 約 576 個詐欺帳戶沒有任何小額交易（且 fraudStep = -1），可能不可辨識 → 會壓低所有模型 recall 上限。
- 若 Week 2 發現 S1 下所有模型都接近完美，研究重點將轉向 S2 與錯誤分析，而非 S1 排名。
- 選用方案：若時間允許（Week 1–2 time-box 6 小時），嘗試用新版 AMLSim 產生含交易層級標籤（`alert_transactions.csv`）與交易類型的資料；本機目前沒有 Java，需 JDK 8 + Maven，可用 Docker 執行。失敗則維持 20K 樣本，不影響主時程。
