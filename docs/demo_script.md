## 1. 開場：研究問題（約 1 分鐘）｜工作區「研究總覽」

**操作：** 停在首頁「研究總覽」。

**講稿重點：**
- 我們想回答：交易之間的「關係」能不能幫助找出可疑帳戶？模型的判斷能不能被解釋？
- 資料是 IBM AMLSim 合成資料：20,000 個帳戶、120,558 筆交易，其中 9.02% 是詐欺帳戶。
- 指出畫面上的長條圖：三個模型在兩種設定下的 test 平均 AP（5 seeds）。
  - S2（拿掉金額特徵）：GraphSAGE 約 0.88、XGBoost 約 0.83、Rule-based 約 0.21。
- 強調：**這是研究原型，分數不是犯罪證據。**

## 2. 資料鑑識：為什麼要有 S1／S2（約 1.5 分鐘）｜工作區「資料鑑識」

**操作：** 點「資料鑑識」，往下捲到「模擬器訊號檢查：小額交易是否暗示標籤？」。

**講稿重點：**
- 畫面顯示：小額交易的兩端「全部」都是詐欺帳戶。
- 這是模擬器產生資料時留下的捷徑，真實世界不會這麼剛好。
- 如果模型只學會「看到小額就判詐欺」，就沒有意義；所以我們設計：
  - **S1**：使用全部合法特徵；
  - **S2**：拿掉整個金額特徵群組，逼模型只能靠交易行為、時間與圖結構。
- 結果：GraphSAGE 在 S2 依然維持約 0.88，表示它不是只靠金額捷徑。

## 3. 模型實驗：比較三個模型（約 1.5 分鐘）｜工作區「模型實驗」

**操作：** 點「模型實驗」，特徵設定選 **S2**，指出 5 個 seed 的點。

**講稿重點：**
- 三個模型使用**同一份特徵、同一個切分、同一組 seeds**，比較才公平。
- 主要指標是 AP（PR-AUC），因為詐欺只占 9%，用 accuracy 會誤導——全部猜「正常」也有 91%。
- 每個模型的門檻都只用 validation 決定；test 只評估一次就上鎖，不能看了 test 再調。
- 5 個 seed 的點分布不大，代表結果不是運氣。

## 4. 帳戶調查：三個代表案例（約 3 分鐘）｜工作區「帳戶與網絡」

**操作：** 點「帳戶與網絡」，設定選 **S2**、Seed **0**、排序模型 **GraphSAGE**，篩選「全部」，在「搜尋或選取帳戶 ID」輸入帳戶編號。

### 案例 A：帳戶 `767`——圖模型抓到、表格模型漏掉

| GraphSAGE | XGBoost | Rule-based | 實際標籤 |
|---|---|---|---|
| 0.9683（正例） | 0.2749（負例） | 0.0000（負例） | 詐欺 |

**講稿重點：**
- 只看帳戶本身的統計，XGBoost 覺得它不太可疑；GraphSAGE 會參考交易對象，給出高分。
- 指著一階交易子圖：它只有 7 筆交易、6 個交易對象。
- （講者備註，平台不會顯示：6 個交易對象中有 3 個是詐欺帳戶，這是 GraphSAGE 能抓到它的合理原因。）

### 案例 B：帳戶 `2828`——誤判（假陽性）

| GraphSAGE | XGBoost | 實際標籤 |
|---|---|---|
| 0.9805（正例） | 0.9201（正例） | 正常 |

**操作：** 篩選切到「假陽性 FP」，選帳戶 `2828`。

**講稿重點：**
- 兩個模型都很有把握地判它可疑，但它其實是正常帳戶。
- （講者備註：它的 7 個交易對象中有 6 個是詐欺帳戶。）
- 這說明「跟可疑帳戶往來」不等於「自己有問題」，所以系統定位是**協助人工檢視的排序工具**，不能自動判定。

### 案例 C：帳戶 `3774`——三個模型都漏判

**操作：** 篩選切到「三模型皆漏判」，選帳戶 `3774`。

**講稿重點：**
- 整個期間只有 2 筆交易，資訊太少，任何模型都很難判斷。
- 誠實說明限制：S2 seed 0 的 test 中有 62 個詐欺帳戶是三個模型都沒抓到的。

## 5. 解釋證據：模型為什麼這樣判（約 1.5 分鐘）｜工作區「解釋證據」→「研究驗證」

**操作：** 點「解釋證據」，SHAP 設定選 **S2**。

**講稿重點：**
- 左圖：XGBoost 整體上最依賴哪些特徵（平均 |SHAP|）。
- 右圖：在「有 SHAP 證據的帳戶」選 `12600`（XGBoost 0.9999、實際為詐欺），說明紅色長條把分數往上推、綠色往下拉。
  - 這個帳戶貢獻最大的是 `out_tx_count`（轉出次數）、`local_density`（鄰居之間的連結密度）、`in_tx_count`（轉入次數）。
- 指出下方的算式：基準值 + 全部特徵貢獻 = 模型分數，證明解釋和模型輸出對得上。

**操作：** 點「研究驗證」→ 研究問題選「解釋可靠性」。

**講稿重點：**
- GraphSAGE 用 GNNExplainer 找出「哪幾條交易關係最重要」。
- 移除重要關係後，模型信心平均多下降約 0.112（和隨機移除相比），代表解釋有抓到東西。
- 但換一個 seed，選出的重要關係重疊度（Jaccard）只有約 0.26——**解釋還不夠穩定**，這是我們的發現之一。

## 6. 研究驗證：結果有多可靠（約 1 分鐘）｜工作區「研究驗證」

**操作：** 研究問題選「圖與時間」。

**講稿重點：**
- **圖結構消融**：拿掉圖衍生特徵（no_structure）時 AP 掉最多；只拿掉鄰居訊息（no_edges）掉得不多。
- **時間轉移**（early_late）：用早期資料訓練、晚期資料測試，兩個模型都明顯下降，說明隨機切分的結果不能直接代表「預測未來」。
- 這些是在看過 E1 test 之後做的**探索性分析**，平台上也有標示。

## 7. 收尾：可追溯與限制（約 0.5 分鐘）｜工作區「方法與來源」

**操作：** 點「方法與來源」，捲到「資料來源與完整性」。

**講稿重點：**
- 每個數字都對應一份封存結果與 SHA-256 指紋；平台只讀取結果，不在網站上重算。
- 限制：合成資料、帳戶層級標籤、GraphSAGE 為 transductive（不是預測全新帳戶）。
- 總結一句：**圖資訊有幫助，但主要來自圖結構特徵；解釋有參考價值，但還不夠穩定，適合作為人工審查的輔助工具。**

## 8. 可能被問的問題

| 問題 | 回答方向 | 主答 |
|---|---|---|
| 為什麼不用 accuracy？ | 詐欺只占 9%，全部猜正常也有 91%；AP 更能反映排序品質 | B |
| 怎麼確定沒有資料洩漏？ | 排除 `fraudStep`；標準化只用 train；選參只看 validation；test 上鎖只評估一次 | B |
| GraphSAGE 和 XGBoost 差在哪？ | XGBoost 只看帳戶自己的統計；GraphSAGE 會聚合交易對象的資訊 | C |
| 為什麼 GraphSAGE 比較好，消融卻說鄰居訊息影響不大？ | 改善主要來自圖結構特徵（如 `local_density`）；GNN 傳遞鄰居訊息的額外貢獻較小，報告中如實呈現 | C |
| 合成資料的結果能用在真實銀行嗎？ | 不能直接推論；這是研究原型，真實資料需要重新驗證 | A |
| 平台能輸入新資料即時判斷嗎？ | 目前不行，平台刻意設計成只讀封存結果，避免網站上重跑 test | C |
| 平台上的子圖是 GNNExplainer 嗎？ | 不是；帳戶頁的子圖只是交易關係展示，GNNExplainer 結果在「研究驗證」 | C |
